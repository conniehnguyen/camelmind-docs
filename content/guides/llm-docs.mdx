# LLMs.txt

CamelMind can generate a machine-readable `llms.txt` file — a plain-text representation of your entire documentation, formatted for AI language models to consume.

The [llms.txt standard](https://llmstxt.org/) is an emerging convention for making documentation sites accessible to AI assistants. When an LLM can read your docs in plain text, it can answer questions about your product more accurately.

## Enabling LLMs.txt

In `camelmind.config.ts`:

```typescript
const config: CamelMindConfig = {
  // ...
  llms: {
    enabled: true,
    directive: "You are reading the official documentation for My Product. Help users understand how to install, configure, and use My Product.",
  },
}
```

### Configuration fields

| Field | Required | Description |
|---|---|---|
| `enabled` | Yes | Set `true` to activate `/llms.txt` and `/api/llms` endpoints |
| `directive` | No | System prompt prepended to the file — context for AI models |

## Accessing the output

Once enabled, two endpoints are available:

| Endpoint | Description |
|---|---|
| `/llms.txt` | Human-readable URL for the full documentation as plain text |
| `/api/llms` | JSON API returning the same content, suitable for programmatic use |

<Callout type="tip">
Point AI tools at `https://your-docs-site.com/llms.txt` to let them answer questions about your documentation.
</Callout>

## Content selection

CamelMind renders all public pages (pages with `roles: []` in `nav.yml`) into the `llms.txt` output. Private or role-gated pages are excluded.

Within a page, use `<LLMIgnore>` and `<LLMOnly>` components to control what appears in `llms.txt`:

### LLMIgnore

Content inside `<LLMIgnore>` is visible to human readers but excluded from `llms.txt`:

```mdx
<LLMIgnore>
This callout is only for human readers and won't confuse AI models.
</LLMIgnore>
```

### LLMOnly

Content inside `<LLMOnly>` appears only in `llms.txt` — it is not rendered on the page:

```mdx
<LLMOnly>
Additional context for AI: this component was introduced in v0.2.0 and replaces the deprecated `Alert` component.
</LLMOnly>
```

This is useful for adding machine-readable metadata, alternative phrasing, or context that would be redundant on the rendered page.

## Output format

The generated `llms.txt` follows the llms.txt spec:

```
# [Site Title]

> [directive]

## [Page Title]

[Page content, formatted as Markdown]

---

## [Next Page Title]

[Content]
```

Each page is separated by a horizontal rule. Headings, code blocks, and tables are preserved in Markdown format. React component markup (callouts, steps, etc.) is stripped to plain text.
