# MDX Components

CamelMind ships a built-in component library available globally in every `.mdx` file — no imports needed.

## Callout

Callouts draw attention to important information. Six types are available:

```mdx
<Callout type="note">A general note.</Callout>
<Callout type="tip">A helpful tip.</Callout>
<Callout type="warning">Something to watch out for.</Callout>
<Callout type="important">Pay close attention.</Callout>
<Callout type="danger">A critical warning.</Callout>
<Callout type="success">A confirmation.</Callout>
```

**Result:**

<Callout type="note">A general note.</Callout>
<Callout type="tip">A helpful tip.</Callout>
<Callout type="warning">Something to watch out for.</Callout>
<Callout type="important">Pay close attention.</Callout>
<Callout type="danger">A critical warning.</Callout>
<Callout type="success">A confirmation.</Callout>

### Custom title

Override the default label with the `title` prop:

```mdx
<Callout type="warning" title="Rate limits apply">
The API enforces a limit of 1,000 requests per minute.
</Callout>
```

<Callout type="warning" title="Rate limits apply">
The API enforces a limit of 1,000 requests per minute.
</Callout>

### Custom icon

Override the icon with any [Lucide](https://lucide.dev/icons/) icon name:

```mdx
<Callout type="tip" icon="rocket">Ready to launch.</Callout>
```

## Steps

Use `Steps` and `Step` for numbered procedures:

````mdx
<Steps>
<Step n={1} title="Install dependencies">

```bash
npm install
```

</Step>
<Step n={2} title="Configure your site">

Edit `camelmind.config.ts` with your title and GitHub link.

</Step>
<Step n={3} title="Deploy">

Push to GitHub and connect to Vercel.

</Step>
</Steps>
````

**Result:**

<Steps>
<Step n={1} title="Install dependencies">

Run `npm install` in your project root.

</Step>
<Step n={2} title="Configure your site">

Edit `camelmind.config.ts` with your title and GitHub link.

</Step>
<Step n={3} title="Deploy">

Push to GitHub and connect to Vercel.

</Step>
</Steps>

## Tabs

Use `Tabs` and `Tab` for presenting alternative content side-by-side:

````mdx
<Tabs>
<Tab label="npm">

```bash
npm install camelmind
```

</Tab>
<Tab label="pnpm">

```bash
pnpm add camelmind
```

</Tab>
<Tab label="yarn">

```bash
yarn add camelmind
```

</Tab>
</Tabs>
````

**Result:**

<Tabs>
<Tab label="npm">

```bash
npm install camelmind
```

</Tab>
<Tab label="pnpm">

```bash

```

</Tab>


</Tab>
</Tabs>

## Details (Collapsible sections)

Use `Details` for content you want to hide by default:

```mdx
<Details summary="Advanced configuration options">

These settings are optional and only needed in specific scenarios.

- `roleMapping` — maps OIDC role names to internal role names
- `publicPaths` — paths that bypass auth even when `requireLogin` is true

</Details>
```

**Result:**

<Details summary="Advanced configuration options">

These settings are optional and only needed in specific scenarios.

- `roleMapping` — maps OIDC role names to internal role names
- `publicPaths` — paths that bypass auth even when `requireLogin` is true

</Details>

### Anchor-linkable Details

Add an `id` to make a collapsible section directly linkable:

```mdx
<Details id="rate-limits" summary="Rate limit details">
Content here.
</Details>
```

Linking to `#rate-limits` in a URL automatically opens and scrolls to this section.

## Code blocks

Standard Markdown fenced code blocks get a copy button and syntax highlighting automatically:

````mdx
```typescript
function greet(name: string): string {
  return `Hello, ${name}!`
}
```
````

**Result:**

```typescript
function greet(name: string): string {
  return `Hello, ${name}!`
}
```

## LLMIgnore and LLMOnly

These components control what appears in the AI-readable `llms.txt` output:

```mdx
<LLMIgnore>
This content is hidden from AI crawlers but visible to human readers.
</LLMIgnore>

<LLMOnly>
This content is only included in llms.txt and not rendered on the page.
</LLMOnly>
```

See [LLMs.txt](/guides/llm-docs) for details.
