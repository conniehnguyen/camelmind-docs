# Navigation

All navigation in CamelMind is defined in a single YAML file — `nav/nav.yml` by default. This file is the source of truth for every URL your site serves, the order of items in the sidebar, and which roles can access each page.

## Basic structure

```yaml
nav:
  - label: "Getting Started"
    dropdown: true
    items:
      - label: "Introduction"
        slug: /getting-started/introduction
        file: content/getting-started/introduction.mdx
        roles: []
      - label: "Installation"
        slug: /getting-started/installation
        file: content/getting-started/installation.mdx
        roles: []
```

Each top-level entry with `dropdown: true` becomes a nav group. Each `items` entry under it defines a page.

### Page entry fields

| Field | Required | Description |
|---|---|---|
| `label` | Yes | Text shown in the sidebar and nav dropdown |
| `slug` | Yes | URL path the page is served at |
| `file` | Yes | Relative path to the `.mdx` source file |
| `roles` | Yes | Array of role names required to access this page. `[]` means public. |

## Decoupled URLs

The `slug` and `file` fields are fully independent. The file can live anywhere in `content/` — the URL is whatever you set in `slug`:

```yaml
- label: "Overview"
  slug: /overview             # served at /overview
  file: content/v2/overview.mdx   # read from this path
  roles: []
```

## Same file at multiple slugs

One MDX file can appear at multiple slugs with independent labels and roles:

```yaml
- label: "Submit an Application"
  slug: /applications/submit
  file: content/applications/submit.mdx
  roles: [vendor]

- label: "Review Submissions"
  slug: /admin/submissions
  file: content/applications/submit.mdx   # same file
  roles: [admin]
```

## Dropdown groups

Top-level entries with `dropdown: true` render as dropdown menus in the top nav. All items inside appear in the sidebar when any page in that group is active.

```yaml
nav:
  - label: "Platform"
    dropdown: true
    items:
      - label: "Architecture"
        slug: /platform/architecture
        file: content/platform/architecture.mdx
        roles: []
      - label: "Security"
        slug: /platform/security
        file: content/platform/security.mdx
        roles: []
```

<Callout type="tip">
Every top-level item must have `dropdown: true`. Flat top-nav links without dropdowns are not currently supported.
</Callout>

## Role-based visibility

The `roles` field controls who can see and access each page:

| `roles` value | Who can access |
|---|---|
| `[]` | All authenticated users (or anyone if auth is disabled) |
| `["admin"]` | Users with the `admin` role only |
| `["vendor", "admin"]` | Users with either the `vendor` or `admin` role |

When a user lacks the required roles, the nav item is hidden from the sidebar **and** direct URL access is blocked. See [Authentication & RBAC](/guides/auth-rbac) for the full auth setup.

## Category labels in the sidebar

Group items visually in the sidebar using category objects — entries with a `label` but no `slug` or `file`:

```yaml
nav:
  - label: "Guides"
    dropdown: true
    items:
      - label: "CONTENT"          # category label (ALL CAPS by convention)
        category: true
      - label: "Writing Content"
        slug: /guides/writing-content
        file: content/guides/writing-content.mdx
        roles: []
      - label: "MDX Components"
        slug: /guides/mdx-components
        file: content/guides/mdx-components.mdx
        roles: []
```

<Callout type="note">
Category entries are display-only — they have no slug and are never served as pages.
</Callout>

## Versioned navigation

When using [versioning](/guides/versioning), each version references its own nav file in `versions.yml`:

```yaml
versions:
  - id: "v2"
    label: "v2 (Latest)"
    nav: nav/nav-v2.yml
  - id: "v1"
    label: "v1"
    nav: nav/nav-v1.yml
```

Each versioned nav file follows the same format. Slugs in versioned nav files are automatically prefixed with the version ID at runtime — you write `/getting-started/overview` and the site serves it at `/v2/getting-started/overview`.

## Changing the nav file location

The nav file path is set in `camelmind.config.ts`:

```typescript
const config: CamelMindConfig = {
  navFile: "nav/nav.yml",   // change this to any path relative to the project root
}
```
