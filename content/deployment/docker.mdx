# Docker & Self-Hosting

CamelMind can run as a Docker container for self-hosted deployments where you need full control over the infrastructure — air-gapped environments, on-prem servers, or private cloud setups.

## Dockerfile

The starter template includes a `Dockerfile`. It uses a multi-stage build to produce a lean production image:

```dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/public ./public
COPY --from=builder /app/package.json ./
RUN npm install --production
EXPOSE 3000
CMD ["npm", "start"]
```

## Building the image

```bash
docker build -t my-docs:latest .
```

## Running the container

```bash
docker run -p 3000:3000 \
  -e CAMELMIND_URL=https://docs.example.com \
  -e CAMELMIND_AUTH_ENABLED=true \
  -e CAMELMIND_AUTH_REQUIRE_LOGIN=true \
  -e OIDC_ISSUER=https://auth.example.com/realms/my-realm \
  -e OIDC_CLIENT_ID=my-docs \
  -e OIDC_CLIENT_SECRET=secret \
  -e SESSION_SECRET=a-random-32-character-string \
  my-docs:latest
```

## docker-compose

For local testing or simple self-hosted setups, use `docker-compose.yml`:

```yaml
version: "3.9"
services:
  docs:
    build: .
    ports:
      - "3000:3000"
    environment:
      CAMELMIND_URL: https://docs.example.com
      CAMELMIND_AUTH_ENABLED: "true"
      CAMELMIND_AUTH_REQUIRE_LOGIN: "true"
      OIDC_ISSUER: https://auth.example.com/realms/my-realm
      OIDC_CLIENT_ID: my-docs
      OIDC_CLIENT_SECRET: ${OIDC_CLIENT_SECRET}
      SESSION_SECRET: ${SESSION_SECRET}
```

Start with:

```bash
docker compose up -d
```

## Nginx reverse proxy

In production, run Nginx in front of the Next.js container to handle TLS termination:

```nginx
server {
    listen 443 ssl;
    server_name docs.example.com;

    ssl_certificate     /etc/ssl/certs/docs.crt;
    ssl_certificate_key /etc/ssl/private/docs.key;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## Health check

The Next.js app responds to `GET /` with `200 OK`. Use this as your container health check:

```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:3000/"]
  interval: 30s
  timeout: 10s
  retries: 3
```

## Environment variables in Docker

Pass environment variables via:
- `docker run -e VAR=value` for individual values
- `docker run --env-file .env.production` for a file
- `docker-compose.yml` `environment:` or `env_file:` blocks

See [Environment Variables](/reference/env-vars) for the full list of supported variables.
